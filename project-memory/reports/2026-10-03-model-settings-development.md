## 实现与测试循环

- `local_app/models/` 管理配置版本、不可变任务快照、系统凭据引用、独立厂商适配器与共享 HTTP 连接池。四家云厂商默认直接连接官方端点，Ollama 使用原生 NDJSON，自定义服务使用 Chat Completions SSE。
- 生成模式默认为 host；independent 模式通过新 `ingest_content` 工具执行整理和保存，query/correlation 返回最终正文、来源、用量和耗时。宿主本身的对话模型不受此配置控制。
- 页面支持连接增删改、模型列表、思考能力检查、带费用提示的连接测试、默认与分任务覆盖，以及本地摄取/索引/问答/关联任务和带认证的 SSE。
- 生成后保存失败可通过检查点重试，避免已成功生成的内容重复计费；模型异常不自动换厂商、回退宿主或重新生成。
- 来源在生成前后、SSE 及历史结果读取时再次核验。发现运行中来源撤回后预览可能滞留，已修复服务端轮询失效返回及前端清理/中止流。
- 发现 Ollama 长度截断可能被当作成功，已改为失败关闭；思考参数以 `/api/show` 的能力及可接受值核验。
- 修复模式切换后旧 host session 无法 finalize 的问题；独立 session 仍拒绝宿主替换正文。
- 实测发现页面显示原始模型输出而非保存后的 Markdown，且模型会编造创建日期。已改为返回实际保存文本，独立生成日期由会话时间确定，模型只负责正文。
- 故障注入发现任务状态写入失败会终止唯一 worker。已保护运行/成功/失败/重试状态写入，失败不发布成功结果；磁盘不可写时明确标注仅在内存保存的失败状态，后续任务可继续。
- 修复 `.gitignore` 的无锚点 `models/` 规则：模型缓存仍在根目录忽略，新 `local_app/models/` 源码可以纳入版本控制。
